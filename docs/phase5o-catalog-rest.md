# Phase 5O Catalog readiness

The Phase 5O specification supplies the official endpoint paths, GET method, Catalog search filter names and `x-api-key` header. The transport implements those operations on the fixed HTTPS host with a five-second deadline, no redirects or caching, and a first-page search cap of 20. Detail, sets and family operations have validated paths. They are not exposed through the owner endpoint pending response review. The existing owner boundary retains its response-size and record caps.

The public docs URL returned a workspace proxy 403. Neither the supplied specification nor the reviewed Phase 5D Sales contract supplies the Catalog response schema. Live registration requires the official search envelope and pagination fields, catalog quota header names and semantics, field types and nullability for UCID/USID/URID/CFID, subjects, set, collector number, variants and print run, and the detail and family response shapes before those paths can be registered. Exact sale linkage also requires separate documented relationship evidence. Synthetic internal fixtures do not stand in for the provider schema.

Once those contracts are reviewed, register the parser and entitlement verifier at the Phase 5N boundary. The owner Preview requires the existing diagnostics and saved-report settings, the explicit catalog enable flag, a dedicated server-side catalog credential, and verified catalog entitlement. The Free Sales key cannot enable or probe Catalog. Then an explicit owner search on the protected immutable Preview can be authorized for the first live test. Phase 5O did not run a live request.
